Local density

The same class on a component is local density, not a second meaning. `.sm` always establishes the same density tokens — only the scope changes. Typography and icons stay the same; only the envelope tightens or loosens.

What participates

Density is opt-in, not a global scale multiplier. Components consume the dimensions that make sense for them; page chrome like alerts, cards, tables, and accordions stays put. Compare the same set of components at default and inside a `.sm` context.

Opt in — button, badge, input, select, pagination, tabs, choice cards, flyout menus, spacing helpers (.py / .px / .mbs / .mbe), and layout primitives via --gap.

  • Controls (.btn, .input, .select, …) consume --control-size.
  • Compact labels (.badge) consume --density-compact-size.
  • Spacing helpers and .choice-card consume --density-space; layouts consume --gap.

No-op — alert, card, dialog, table, accordion, navbar, and page sections keep their size. The alert and card above are identical in both columns even though their inner button and badge shrank.

Inline choices (.check, .radio, .switch) are a no-op too, and deliberately so: they sit on a line of text, so they follow --choice-control-size off the control typography, which density does not touch. Shrinking the checkbox but not its label would break the alignment density is not asking to change. Size them with --control-font-size or --choice-control-size instead.
