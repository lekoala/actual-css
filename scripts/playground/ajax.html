Responses

422 Unprocessable Content
The request arrived and was understood, but the data is invalid: a taken email, a date in the past. The server answers with the form's errors as HTML, so the target is updated. It is the usual status for server-side validation, and the one case outside 2xx the module displays. response.ok is false: the application knows nothing was saved.
500 Internal Server Error
The server failed: an exception, a database down. Its body is an error page or a stack trace, not something to show inside a form, so the target stays as it was. The event still fires with the response; the application decides what to say.
JSON
A 200, but not HTML: the module never guesses how to render data. The target stays as it was; the response reaches ajax-response, where the application reads it.
Slow 3 s
Past --busy-delay: the form overlay fades in. Further clicks are ignored until the answer arrives (one request at a time).
Redirect
The server answers 303 to /done (post/redirect/get, the usual answer after a save). fetch follows it, then the module navigates to /done like a native submission: the page leaves, and /done is requested twice.
Redirect off-origin
The 303 points to another origin, which sends no CORS headers, so fetch fails: ajax-error, no response, the target unchanged. The same happens when the network drops. A login redirect to an SSO provider takes this path.

Abort

Send, then remove the form while it waits: no event follows.
